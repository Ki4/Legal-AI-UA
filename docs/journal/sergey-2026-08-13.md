# 2026-08-13 — six PRs, and the lessons that fit in none of them

`docs/CONTRIBUTING.md` does not ask for an entry: this session produced six pull requests, and each
documents itself. Writing one anyway for the part that has no PR to live in — what happened to the
work rather than what changed in it.

## What landed

Two questions that had been open since July are closed. **ADR-0016**: the core is Python, and the
contract is a schema rather than a type either side owns. **ADR-0017**: the two cloud-only objects
found by `db diff` on 2026-08-12 are decided — the sequence revoke into a migration, the `ensure_rls`
trigger left as a recorded divergence. Alongside them: `team` moved onto the `api/` layer, so no
feature queries Supabase from a component any more; `packages/ui` gained `Select`; `packages/i18n`
exists and the console shell speaks both languages. Tests 95 → 123, SQL scenarios 98 → 104.

## A settled decision, reopened by the person meant to be reading it

Twice this session the assistant asked which of two paths to take. The first — TypeScript or Python
for the core — was genuinely open, because ADR-0004 had explicitly left it so.

The second was not. Before starting `packages/i18n`, the assistant asked whether `uk` should be the
default and which dictionary should be the source. **ADR-0006 had answered that on 2026-07-30**: `uk`
primary, `en` second, adding a locale is one line. The answer came back, correctly, that language did
not look like a problem — the users are Ukrainian, the repository is English, and the two facts are
unrelated.

The cost was small here and the shape is not. An ADR exists so a decision is made once; an assistant
that proposes a fork without reading the ADR on that subject converts a recorded decision back into
an open question, and the record silently stops doing its job. The rule that follows: read the ADRs
on the topic **before** framing a choice, not before implementing one. The half-life of this failure
is long — nobody notices a decision being re-litigated, because re-litigating looks like diligence.

## An adversarial probe that damaged the thing it was probing

Recorded in ADR-0017 with its consequences; here for the mechanism, because it generalises past
sequences.

Both new assertions in `verify_grants.sql` were checked red before being trusted green: the grant was
restored and `setval` attempted, and a table was created without RLS. Both went red as intended. Then
every other verification script died on a primary key collision it had not caused.

**Sequence operations are not transactional.** The probe ran inside a transaction and ended in
`rollback`, and the sequence stayed where `setval` left it. Nothing in the script was wrong; the
assumption that a transaction bounds the blast radius was.

Two things came out of it. The severity argument in the migration stopped being theoretical — the
damage a stray `setval` does is damage no transaction takes back. And the first draft of
`verify_grants.sql` carried the identical landmine: it attempted the destructive form of the call,
which is safe only for as long as it keeps being denied. The day the revoke regressed, the script
would have proved the regression by corrupting the sandbox it verifies. It now passes the sequence's
own current value, read back first as the owner: same privilege check, no blast radius.

The general form is worth keeping: **a verification script whose failure mode damages the
environment is not a verification script.** Ask what the forbidden call does if it succeeds, not only
whether it is refused.

## What could not be verified, and why that is written down rather than skipped

`Select` shipped without the both-themes screenshot its own DoD requires (design spec §11 —
"dark breaks silently on shadows and overlays"). The gallery is behind `RequireAuth`, and three
screenshot attempts against a local dev server hung, most likely on the session request.

The likely cause is worth recording because it will cost the next session the same hour:
`apps/console/.env` defines `VITE_SUPABASE_URL` **twice**, once local and once cloud. The file is not
in the repository, so nothing here can fix it, and nothing here can notice it either.

## Three things nothing now enforces

Named because a green gate that never executes the thing which would have gone red is the failure
mode this repository keeps meeting from new directions.

- **Fixture rows and their dependants.** `usr-pending` was added to `mockProfiles` because the team
  screen's whole reason to exist was untestable without an unapproved registration. Its dependants
  were found by reading — `listAssignableLawyers` filters on role, so the picker test still passed,
  and it gained an assertion that a pending registration is not offered. Nothing makes that
  connection automatic: a future row can quietly change an assertion in another feature.
- **The real `approve_user` and `app_metadata`.** The console test covers the row → view model
  translation and the two round trips against a stubbed client. That the RPC actually writes the role
  into `auth.users.raw_app_meta_data` — which is what the JWT reads, and therefore what access
  control believes — was checked by hand against the sandbox and is covered by no script.
- **Token discipline in `packages/ui`.** "No hardcoded colors, sizes, or durations" is a DoD line
  checked by grepping the new component by hand. It is mechanical, decidable, and a good candidate
  for `check:sql`'s sibling — a static check over the design system.

## Left open

- The `ensure_rls` function's body has still never been read. ADR-0017 records the divergence as
  accepted on exactly that condition — it is a net, never the mechanism.
- `approve_user` does not check that its target has no role, so it is already the role-change
  operation ADM-33 has not built a screen for. Not fixed: that is a migration, Tier 2 and access
  control both.
- Every console feature screen still holds its copy in JSX. The shell is bilingual and the catalogue
  underneath it is not.
- `anatomy` still bypasses the `api/` layer — the cheap half, with no queries to move.
- `lint-staged` now matches `*.py` while `ruff` is not installed anywhere. The first Python file
  fails its hook, which is the direction ADR-0016 asks for.
- Access-control migrations merged under the one-developer suspension clause now include
  `20260813120000_explicit_sequence_grants.sql`. The list is owed a review when a second developer
  exists.
