# 2026-08-14, second session — paying the debts that make gates honest

The day's first entry is `sergey-2026-08-14.md` and ends with a list under "Left open". This
session picked that list up rather than starting anything, so most of what follows is about how the
work went. What changed is in the PR and in `docs/ROADMAP.md`.

Three agents in parallel again, one checkout, the orchestrator holding the shared files.

## The shared file is written before dispatch — and then nobody commits

`package.json` needed an entry from two different zones: `check:copy` for the checker and the
`lint-staged` `*.py` route for the Python guard. Written first, by the orchestrator, and both agents
forbidden from touching it. That much was carried over from this morning and worked again.

What was new, and is the thing worth writing down: **the orchestrator must not commit while agents
are running.** The pre-commit hook is `lint-staged`, which stashes unstaged changes, runs its tasks,
and restores them. An agent writing a file inside that window is racing a stash. One commit was made
mid-session — the ADR addendum, whose files no agent owned — and it came out clean, which is luck
being indistinguishable from safety. Every other commit waited until all three had reported.

## Two of three agents verified with `tsc` and called it verified

The briefs said to run `npx tsc --noEmit` and nothing else, because three agents racing `pnpm lint`
and `pnpm test` fight over the turbo cache. That instruction is right and it has a cost that was not
anticipated: an agent told to run one gate reports "verified" meaning that gate.

`pnpm lint` at the root then failed on three errors `tsc` cannot see — `serviceRowQuery`,
`serviceDetailRowQuery`, `teamRowQuery`, each "assigned a value but only used as a type". They were
module-scope query builders constructed on import and never awaited, existing solely to be
`typeof`'d.

The rule was describing the design accurately, which is the reason not to reach for
`eslint-disable`. A value pretending to be a type is also a `PostgrestFilterBuilder` built on every
import for nothing. The fix was to derive the type from a query the code actually runs — a named
function used by the real call sites, `QueryData<ReturnType<typeof fn>>` — which is a stronger claim
than the phantom made, not merely a quieter one.

**The orchestrator running the full set once, after merging, is not ceremony.** It is the only place
the gates the agents were told to skip actually run.

## Reviewing the design, not the diff

Closing the `.returns<T>()` hole forced the runtime-composed select string into two literals,
because `QueryData` can only infer from a literal. `SELECT_BASE` and
`SELECT_INNER_JOIN_ASSIGNMENTS` differ by one `!inner` and are otherwise identical — which looked
exactly like the hole being moved rather than closed. Two copies that must stay in sync is the
shape the whole session was about.

Reading it could not settle it, so: drop `label_uk` from the inner-join literal **only**, run `tsc`.
Red, at `toPracticeAreaRef`. The union of the two branches is what carries it, so divergence is
caught and the duplication is a cost to readability rather than a defect. The same probe on
`team.supabase.ts` also turned the test fixture red, which was not predicted.

The general form: **an agent's design can be correct for a reason the agent did not state, and the
cheapest way to find out is to break it.** A diff read carefully still only tells you what the code
says.

## Migrating a feature changed which states it has

`anatomy` was the cheap half of the `api/` migration — a hardcoded trace, no queries. The brief said
so. But going through the contract made the screen asynchronous, and the first version handled
neither of the states that created: no `.catch()`, and `trace?.blocks ?? []`, which renders loading,
empty and failed as the same blank list. The agent did what it was asked; the ask changed the
screen's state machine.

Worth expecting rather than rediscovering: **a refactor described as mechanical can still be the
thing that introduces a state.** The reference says it out loud — `useCatalogue`'s header, that
components get data, loading and error from a hook and never see a promise — and the migration was
not measured against it until review.

## The debt that was cheapest of all

`ensure_rls` had been sitting on the "left open" list since 2026-08-13, described as needing access
this repository did not have. It needed `supabase db dump --linked`, and the credentials were
already cached. Nobody had tried.

The function does not do more than switch row security on, which is what ADR-0017's last consequence
asked to be told, so the decision stands. Two things it does that the decision did not know: it
swallows a failed `alter` into the Postgres log, and it creates no policy — so a migration that
grants a client role its `select` and forgets `enable row level security` gives a working screen in
the sandbox and an empty one in the cloud. Recorded as a dated addendum rather than an edit to the
decision, because an ADR is a record of what was decided and when, not a description of the current
state of the author's opinion.
