# 2026-08-15, second session — four PRs, and the instrument that could not answer

ADM-57, ADM-63 and ADM-66 landed as #50 through #53, so what changed is in their descriptions. What
follows is the part that fits in none of them.

## Splitting one backlog row into two PRs was the right call and cost nothing

ADM-66 is one row and shipped as two pull requests, the list and the card. `docs/CONTRIBUTING.md`
puts a ~400-line ceiling on a PR and the pair together is about four times that. What made the split
cheap rather than administrative is that the seam was already there: the list needed the contract,
the view models and the feature folder, and the card added one operation to each. Neither PR is a
half of something.

The same shape had already appeared earlier in the day, when the session was asked for ADM-63 and
expanded to ADM-57 on the grounds that the two overlap. They do — and the useful consequence was
ordering, not sharing. Building entitlements first is what let `orders.entitlement_id` be a real
foreign key in the first migration rather than a nullable column added later to a table that already
has rows.

## The most valuable check of the day could not have been a test

The order card renders an entitlement in three states, and one of them exists only under RLS: a
purchase that is **recorded and not readable**. Every unit test of it passes against a screen that
also gets it wrong, because a test supplies the view model that the bug would have produced.

What settled it was opening one URL as two people. As an admin: "One-off purchase, valid until the
law changes". As Olena, attached to the service: "recorded, an admin can read it". Same code path,
same order, different reader, different sentence.

That took a detour — the seeded lawyers had no passwords, and hand-inserted `auth.users` rows fail
in two different opaque ways. `Database error querying schema` covers a null in the token columns
and, separately, a null in `raw_user_meta_data`, `created_at` or `updated_at`. `Wrong email or
password` covers a null `instance_id`. All three are GoTrue scanning into non-nullable Go values,
and none of the messages points anywhere near the cause. It is now in `seed.sql` with the reasons
written beside it, so the next person spends none of that time.

## An instrument that gives contradictory answers is not evidence

DoD §8 asks for a screen seen in both themes. The browser extension's screenshot never worked on
this app — its injection waits for a `document_idle` the page apparently never reaches — so I tried
to measure the themes instead, reading computed colours across a toggle.

The numbers contradicted themselves. The same `data-theme` produced a light background in one run
and a dark one in the next; `--ui-canvas` flipped correctly every time while `body` appeared to lag
a toggle behind, and my own attribute writes turned out to be racing React's. There was a real
temptation to write up "the light theme is broken", because two of the readings said exactly that.

It would have been wrong to. Not because the app is certainly fine — I do not know that either —
but because an instrument that answers differently on identical input has not measured anything, and
a defect reported on that basis costs somebody an afternoon proving a negative. The honest outcome
is that the debt stands unchanged and now says _why_ no instrument currently available can close it.

The same discipline caught a smaller one earlier: I told Sergey that `AUDITED_TABLES` did not know
any of the six new tables, and it was two. The other four are absent by a documented decision that
was sitting three lines above the list I was looking at.

## What the gates caught that review would not have

Three verification scripts went red because `seed.sql` gained rows of a kind they counted. They had
assumed an empty baseline for as long as one happened to exist. That is the second time this week a
green check turned out to be measuring the absence of data rather than the presence of a rule — and
unlike the first, this one failed loudly the moment the assumption stopped holding, which is the
whole argument for running them in CI rather than by hand.
