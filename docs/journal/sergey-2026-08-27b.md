# 2026-08-27b — the field dictionary, and a debt that was never about the instrument

Second session of the day. The first settled the product shape; this one built ADM-18 and ADM-19.
What went into the code is in the PR. What follows has no other home.

## The both-themes debt was a wording, not a wall

It had stood since `2026-08-14`, phrased as "DoD §8's second half has no instrument: jsdom applies
no stylesheet and the browser extension cannot screenshot this app". Both halves are true. The
conclusion does not follow from them, and nobody noticed for thirteen days because the sentence
reads like a finding.

Docker was already running on this machine. `pnpm exec supabase start` brings the stack up in about
a minute, the console has a `.env` pointing at it, and Playwright is in the environment. From "no
instrument" to two screens in both themes was fifteen minutes, most of it spent seeding data.

The lesson is not "use Playwright". It is that a debt written as a diagnosis stops being re-examined
— the next reader inherits the conclusion instead of the problem. A debt is better written as what
is missing than as why it is impossible.

## The first look found what the debt existed to find

`Button` primary in dark: white on `--ui-brand`, measured in the page at **2.54:1** against AA's
4.5:1 floor. Every screen, starting with login, since the day the theme was added.

None of the 472 tests can see this and none ever could. jsdom applies no stylesheet, so a component
test can assert that a token was used and never that the result is readable. `tokens.css` already
carries a careful paragraph about exactly this for the status colours — `--ui-warn-ink` exists
because `--ui-warn` measured 3.7:1 — and the accent got the same treatment nowhere. The care was
real and it was applied to the colours somebody happened to measure.

Recorded as a debt rather than fixed here, because changing the primary button's colour is a
design-system decision that touches every screen and deserves its own change.

## The seed and the SQL fixtures were coupled, and only running them said so

`verify_law_refs.sql` died loading its fixtures: `law_norms_watched_once` is unique on
`(source, act_id, article)`, and the script inserted article 105 of code 2947-14 — which `seed.sql`
had just gained. The script's own header says the counts are scoped by an id prefix "because a
script that assumes an empty baseline fails on the seed rather than on the schema". The author saw
the class of problem and the prefix does not defend against it: an id prefix scopes counting, and
only a value nothing else would use scopes uniqueness. Fixtures now cite `test-0001`.

Worth being precise about what caught it: `pnpm verify:sql`, run by hand at the end of the session.
CI would have caught it too, on the PR — `sql.yml` runs on any change under `supabase/`. So the
mechanism was there and the feedback was merely late. That is a much better position than the
contrast finding, where no mechanism exists at all.

## What I chose not to build

- **The field map** (used / extra / missing) from §4.4. It needs ADM-20's block ↔ field links, and
  the spec is explicit that without them the three colours are guesses. A map that guesses is worse
  than no map, because `missing` is the colour that is always a defect.
- **Drag-to-reorder**, replaced with buttons. Written into §4.4 with the reasoning rather than left
  as a silent difference between the spec and the screen.
- **A per-language shape for `select` options.** ADM-18 had to write the column and picked a flat
  list of strings; that is a decision, and it is now Q26 rather than an assumption buried in a type.

## The recipe, so the next person does not re-derive it

```bash
docker version                      # already running here
pnpm exec supabase start            # stack + migrations + seed
pnpm --filter @legal-ai/console dev
# olena@example.test / sandbox — a lawyer assigned to the divorce service
pnpm verify:sql                     # 252 scenarios across 11 scripts
```

Nothing runs the browser half automatically. That is the debt as it now stands in STATE.
