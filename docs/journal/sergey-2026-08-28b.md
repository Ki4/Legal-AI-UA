# 2026-08-28b — the gate that could only fail where it was told to

Three PRs landed (#55, #56, #57) and each documents what it changed. This entry exists because one
lesson belongs to none of them: it appeared in two different files, at two different levels of the
stack, in the same afternoon, and the second time it was hiding inside a test written to catch
exactly this class of problem.

## What was tried

**Every claim was checked by injecting the defect it claims to catch.** Twenty-nine of them —
thirteen against the anatomy mapper in #56, sixteen against the frozen contract in #57. That habit
is the repository's, not this session's; ADR-0021's own journal ends on it.

Twenty-eight went red on the first try. Two did not, and both were the same shape.

**The degenerate fixture.** The mapper test's sample had one block, with `needs_attention: true`
beside a non-empty `law_refs`. Rewriting the mapper as `needsAttention: block.law_refs.length > 0`
left it green, because on that one block the wrong reading and the right one agree. Two blocks with
the opposite pairing fixed that and let the _inverted_ reading — `length === 0` — through instead.
With one boolean varying across two rows, any other varying binary is either perfectly correlated
with it or perfectly anti-correlated, so exactly one of the two derivations always survives. Three
rows are the fewest that break both.

**The checker that checked its author's list.** `schema.test.ts` gained an assertion named "has a
case for every constraint keyword the schema uses" — written so a constraint could not be added to
the schema without a failing case being added to the fixtures. It walked the schema and matched each
key against a written list of constraint keywords. Adding `maxLength` to the schema left it green: a
keyword nobody had thought of was, by construction, not on the list of keywords to check for. It now
counts by exclusion — anything that is not a known structural or annotation keyword is a constraint
— and both halves were run: red with `maxLength` added, green once its case was supplied.

## What was learned

**A check that can only fail in the cases its author enumerated is not a check, it is a summary of
what its author already believed.** That is one sentence covering both failures above, and it covers
them at two levels: a fixture enumerating the data shapes worth distinguishing, and a walker
enumerating the constraints worth noticing. Both were written carefully. Both read correctly. Both
were fail-open at the exact point they claimed to be fail-closed.

**The tell is grammatical.** Both defects were introduced by an `includes`-shaped thought — "is this
one of the things I care about?" — where the fail-closed form is an exclusion: "is this one of the
few things I know to be harmless?" A gate written the first way grows blind spots by default,
because the world adds cases and the list does not. A gate written the second way goes red when the
world adds a case, which is noise on the day it happens and correctness on every day after.

**Reading cannot find this, and that is the load-bearing part.** Both defects survived being written
carefully and re-read. What found them was injecting a defect and watching for red — and, crucially,
injecting one the author had not already listed. `maxLength` was chosen because it was _absent_ from
the list, which is a different move from testing the cases the code names.

**This is ADR-0021 §3's argument, one level down.** That ADR records why `additionalProperties:
false` plus full `required` proves less than it appears to: it pins key sets and says nothing about
values. The same gap reappears wherever a proof is taken over the axis somebody happened to think
about. It is worth expecting at every level rather than filing under "the schema thing".

## What was abandoned

Nothing was abandoned, but one thing was deliberately not done and is worth naming: the twenty-nine
injections are still transcript-only. `pnpm probes` — written on 2026-08-27 for exactly this, after
the same complaint — reaches neither `packages/core-client` nor `features/anatomy`. So this session's
evidence is on the same expiry schedule as the evidence that produced the probe runner in the first
place. It is STATE's 2026-08-27 debt, and it did not shrink today. It grew from four to twenty-nine.

Also not done: the anatomy screen was never looked at, through two merged PRs that changed how it
renders. Five attempts through the Chrome extension timed out; Playwright answered in one call —
the route redirects to `/login`, the console is clean, `RequireAuth` is working. So the DoD §8 item
is not blocked on tooling, it is blocked on a signed-in human. Worth recording because "the tool is
broken" was the wrong diagnosis for four of those five attempts, and one call to a different tool
was cheaper than the fifth retry of the same one.
