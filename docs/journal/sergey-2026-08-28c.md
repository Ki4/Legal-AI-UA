# The gate that guards the gates is not run by anything

2026-08-28, third entry of the day. Written because it fits in no PR: it was found by closing the
session, not by doing the work, and it is about how the work is checked rather than what changed.

## What happened

ADM-3's last two passes went out as PR #58 and merged green. The session had done what this
repository asks of a change that adds assertions: nineteen defects injected by hand, each into real
source, each expected to turn a named test red. Eighteen did. Sixteen of them then became probes in
`scripts/probes.mjs`, so the demonstration stops being a sentence in a PR description and becomes
something a command re-runs. `pnpm probes` reported twenty-six run, twenty-six caught.

Then `/session-end` archived the oldest ROADMAP section — "the debts get mechanisms" from
2026-08-27, the session that wrote `pnpm probes` in the first place — and the archive rule asks one
question of every lesson on the way out: is this carried by a gate, by a rule, or by nothing?

`pnpm probes` is carried by nothing. `.github/workflows/ci.yml` runs lint, typecheck, test,
docs:check, check:sql, check:copy, check:contrast and build. The pre-push hook runs docs:check.
Nothing anywhere runs the probes. Every probe result this repository has ever seen was produced by a
person typing the command.

## Why it stayed invisible

Because the probe suite reports success, loudly, and success from a suite nobody is obliged to run
reads exactly like success from a suite CI runs. The failure is not in the output; it is in the
absence of a caller, and no output can show an absence.

There is a second reason, and it is the more uncomfortable one. `pnpm probes` was itself the fix for
"a drift case demonstrated once in a PR description is never re-run". It landed as the mechanism, so
it was mentally filed as the thing that closed the debt — and nobody asked the next question, which
is what runs the mechanism. A tool written to make a manual habit executable is worth exactly as
much as its own execution schedule, and it inherited the habit it replaced: run when somebody
remembers.

## What was tried and abandoned

Adding a CI step in the same session, as a one-line fix. Abandoned as a decision that should not be
taken quietly: twenty-six probes are twenty-six Vitest runs, and the honest options differ in cost
and in what they protect.

- A step in `verify`, on every PR. Simplest, and turns a fifty-second job into several minutes.
- A separate job in the same workflow, running in parallel. Same total compute, no wall-clock cost
  to the developer, one more required check.
- A path-filtered job — only when `packages/**` or `apps/**` source changed. Cheapest, and it is the
  one whose failure mode has to be thought about: a probe rots when the _code_ moves, so filtering
  on source is filtering on exactly the right thing, but a change to `probes.mjs` alone must be in
  the filter too or the file that lists the probes can break its own list unobserved.
- Nightly. Cheapest of all, and it decouples the signal from the change that caused it, which is the
  property that made the PR-description habit useless in the first place.

Recorded in STATE with those shapes named, rather than resolved at the end of a session by the
person least likely to argue with themselves.

## The other thing the injections said

One of the nineteen stayed green, and it was not in the code — it was in a test. "Produces the same
job twice" compared two runs of the fixture client inside one process and asserted they matched. A
module-level `const EPOCH = Date.now()` passes it: the epoch is read once, both runs share it, and
the assertion is satisfied by a fixture that produces different values tomorrow than today.

The test read as a determinism claim and was a within-process-stability claim. The fix is small — the
timeline is asserted against instants written down in the test — but the shape is worth carrying:
**a second run is not an independent witness.** Comparing an output against another output of the
same program tests less than it appears to; comparing it against a value somebody wrote down tests
what was meant. This is the same family as the constraint-coverage checker that counted by inclusion
and could only see the keywords its author had thought of, found on 2026-08-27 and recorded a day
earlier in this journal — a check whose reference point comes from the thing being checked.

## What carries this now

- The `pnpm probes` gap: a dated debt in `docs/STATE.md`, with the four shapes above, and the first
  of the next candidates. Not a gate — that is the point of the entry.
- The weaker-test lesson: the comment in `fixture-client.test.ts` that says why the obvious version
  was not enough, and the probe `fixture-timestamps-come-from-the-wall-clock`, which is the injection
  that found it, made repeatable.
- The habit that found both: injection before belief. It is in `docs/CONTRIBUTING.md` as the
  verification rule and in `packages/core-client/README.md` as a table of which command catches
  what. Nineteen injections cost about twenty minutes and moved two things from "believed" to
  "seen" — one of which was a test that had been written that same hour.
