# 2026-08-28 — the debt that was a number, and the screen nobody had opened

PR #59 carries what changed. This is the part that fits in no PR description, because it is about
how the work went rather than what moved.

## A debt stated as a count is not actionable

STATE carried "twenty-nine drift cases are still re-run by hand". The session that wrote it knew
exactly which twenty-nine. Twenty-four hours later, closing it meant reconstructing the list from
`ROADMAP.md` and a paragraph in `packages/core-client/README.md` — and the two disagreed, because
the number came from one session and "three of them stay manual" came from another, and they
overlapped without saying so.

The count was never the debt. The members were, and no file held them. What made it recoverable was
luck: both sessions had written prose good enough to reconstruct from. A debt three weeks old with
the same shape would have been unrecoverable, and the recovery would have looked like re-doing the
work rather than like finishing it.

So: a debt names its members, or names the file that enumerates them. A count is a summary of a
list, and writing the summary while discarding the list is the move that cost this session an hour.
It is not a new rule so much as the same rule the probes exist for — evidence that lives only in a
transcript has already expired — applied one level up, to the record of what is owed.

## "Inexpressible" was a claim nobody re-tested

Three cases had been written into a README as impossible to probe. Two of them were not hard: they
needed a **different checker**, not a different case. The `…AreExhaustive` bridges are types, Vitest
transpiles types away, and the probe runner only knew how to run Vitest — so the limit was in the
tool and got recorded as a limit in the world. The third was described as needing a patch that
declares something; it needed `globalThis`, which is one text replacement.

Worth noticing what kind of error this is. Nothing was wrong when it was written: at the time, with
that runner, those cases genuinely could not be probed. The defect is that the sentence outlived the
condition it described, sitting in a README as a standing fact. The same class as a stale ROADMAP,
and the reason this repository sorts documents by when they are read.

## The screen, and what a tool could and could not do

The anatomy screen had never been opened, and its data path had changed the day before. The debt
said it needed a signed-in human. Half of that turned out to be false: the local Supabase stack, a
seeded admin, and a browser driven from here covered both themes, the console, and the semantics —
mechanical work that was being described as human work because nobody had tried.

The half that was real stayed real. Three findings came out of it and not one is something a gate
could have raised: the screen is hardcoded English where `apps/console/CLAUDE.md` says dictionary
keys only; `template` renders as "Confirmed by lawyer", which is a claim about a lawyer's
involvement that the schema does not make; and `selected_by` and `tool_calls` are carried by the
trace and rendered nowhere, which is half of what the screen exists to answer. The first is a rule
violation a checker could plausibly catch and does not. The other two need somebody who knows what
the screen is for — and the second needs a lawyer, not a developer.

## What was abandoned

Aiming a probe at a single `it` rather than at a test file. Vitest takes a path; several assertions
share `schema.test.ts`; and the alternatives — splitting the file to suit the prober, or matching on
test names — both make the tests worse to serve the tool. The concession is written into
`probes.mjs` instead, where the next reader meets it rather than deduces it.
