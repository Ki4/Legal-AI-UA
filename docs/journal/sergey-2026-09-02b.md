# 2026-09-02b — a debt that named its evidence, and two predictions nobody watched

PR #70 documents what changed. This is about how the session went, which fits in no PR.

## Two predictions came true on the same day, and neither was watched by anything

ADR-0024 called the unexercised import map "the weakest point of this decision and the one to
revisit first". It broke three days later. `20260813120000` wrote that `service_role` already holds
no DML on public tables, "so the gateway will have to be granted what it needs explicitly when it
lands" — the fetcher was that gateway, and nobody was watching for the day it landed.

Both predictions were correct, dated, and load-bearing. Neither was a mechanism. A prediction in a
comment tells the next reader what to expect; it does not tell them _when_, and it cannot notice.
The repository is unusually good at turning lessons into gates and this is the failure mode that
survives that habit: the thing you wrote down because you could not gate it yet.

There is no general fix, and inventing one here would be the wrong lesson. What is available is
smaller: when a document predicts a failure conditional on an event, the event is the thing to put
somewhere a session will trip over — a debt, a next candidate, a line in STATE — rather than the
prediction.

## A debt phrased as "what holds this claim" beats one phrased as a task

The entry read: _the fetcher has never run under Deno — the import map and all of `index.ts` are
held by the compiler and nothing else._ That phrasing is why it was pickable, and why the payoff was
legible within twenty minutes of Docker starting. It named the evidence that was missing rather than
the work that was undone. "Wire up the fetcher" describes the same debt and teaches nothing: it
sounds like effort remaining, so it competes with features and loses.

The debts written this session are phrased the same way on purpose. "Nothing automated ever runs an
edge function" is not a task; it is a statement about what currently carries a claim.

## Abandoned, and why

**Moving `packages/law-refs` under `supabase/functions/_shared/`** and re-exporting it from the
package. One source, no script, nothing to synchronise — and a layout asserting that the console's
citation parser belongs to the edge functions. The console imports it to normalize a citation a
lawyer pasted and does not run on Deno. Rejected on what it would say, not on what it would cost.

**A committed copy with a drift check**, in the shape of the `core-client` bridge tests. It is the
familiar pattern in this repository and it is strictly weaker here: a gate that must keep being run,
guarding against a state that need not exist at all.

**`pnpm` injected workspace dependencies**, so `node_modules` inside the mount would hold real files
rather than a symlink out of it. Possibly workable, resting on hard-link behaviour across a Windows
bind mount and on the edge runtime resolving bare specifiers through `node_modules`. Two guesses
about other people's tools where the copy is one fact about ours.

## One process note

Migrations and security boundaries are on `docs/CONTRIBUTING.md`'s never-delegated list, and this
session was almost entirely those. Working it in the main thread was the policy rather than a lapse
from it — worth recording once, because the delegation protocol became repository policy only
yesterday and its first real application is the kind of thing that gets misread later.
