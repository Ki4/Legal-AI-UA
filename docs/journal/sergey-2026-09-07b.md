# 2026-09-07b — an answer that collided with a decision, and a delegation that should be visible

Both PRs of this session document what changed. These two are about how the work went, so they have
no PR description to live in.

## A verbal answer does not outrank a recorded one, and the fix is a question rather than an edit

Asked directly who should publish a service version, the product owner said a lawyer should be
accountable for it — "but not all of them, which is why the co-owners are advocates". §13 carries a
line recorded as settled that says the opposite in the same words: the split inside the catalogue is
commercial versus professional, **not senior versus junior**.

Both readings are defensible and the collision is not the interesting part. What is worth keeping is
what it costs to resolve either way. Rewriting §13 to match the answer takes one edit and destroys
the record that a different decision was once made deliberately — the next reader finds a spec that
has always said this. Ignoring the answer takes nothing and leaves the product owner's actual intent
unrecorded anywhere.

So it became Q28: the question, both positions, a recommended answer that satisfies each (publication
is two acts, and "not every lawyer" rides on assignment rather than on seniority), and an explicit
note that ADR-0026 is written so either answer changes the publish site alone. §13 now points at it,
so the settled-looking line no longer reads as settled. The general form: **when an answer collides
with a recorded decision, the output is a question with both sides, not an edit to whichever one is
in front of you.**

## Which parts of an ADR were argued and which were delegated

One of three questions put to the product owner came back as "I don't know, what do you think is
right, what are the best practices" — the auth contour for clients. The decision in ADR-0026 (one
Supabase project, `actor_type` as a separate single-valued axis) is therefore the assistant's, made
on request, and it reads in the document exactly like the two that were argued over.

That is worth saying out loud once rather than hiding: an ADR records what was decided, and a reader
six months from now cannot tell which paragraphs had a second opinion behind them. Nothing in this
repository distinguishes them today, and inventing a marker for it would be worse than the problem.
What is cheap is naming it here, where the question of _how_ the session went belongs.
