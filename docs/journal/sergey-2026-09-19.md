# 2026-09-19 — the walk found what the tests could not, and the tool that walked it was not the one configured

Two PRs (#88, #89) document what changed. This is about how the day went.

**Asked:** close the previous session, then build the versions tab (ADM-32).

**Done:** in that order. The close came first and cost twenty minutes; the feature followed with
its acceptance criteria written before the code, as §9 of the DoD asks.

**Learned:**

- Fifty-six tests were green and the screen had a defect a person meets on the second click: a
  refusal shown outside a native modal. jsdom does not know that `showModal()` makes the page
  inert, so "the alert is in the document" was true and useless. The walk against Postgres found
  it in one race — two pauses on one version, one from the browser, one from `psql`. DoD §8's line
  "the screen seen rendering" is not ceremony; it is the only reader a modal has.
- The Chrome extension could run JavaScript in the page and could not take a screenshot — every
  capture timed out while `document.readyState` said `complete`. The configured Playwright MCP
  server had not connected either. `npm i playwright` in a scratchpad and
  `chromium.launch({ channel: "chrome" })` walked both roles, both themes and both languages in ten
  minutes, with no browser download. The script is the debt in STATE: it is the first executable
  form the DoD's screenshot line has had, and it lives where the next session cannot find it.
- The fixture caller was the wrong person for the happy path. `sv-alimony-1` is Taras's own draft
  in an area where Olena also signs — exactly the version the four-eyes rule refuses — and three
  tests written for "a signatory releases" failed on the rule they were meant to prove. The rule
  was right; the tests had assumed the world before ADR-0027.

**Abandoned:** creating a version from the tab. §4.3 lists it; a button with no editor behind it
would be a promise the console cannot keep, so the tab has a screen and no way in, and STATE says so.
